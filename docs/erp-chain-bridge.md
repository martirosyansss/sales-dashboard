# ERP կամուրջ՝ «Տրամադրում և վաճառք» շղթայի համար

Այս փաստաթուղթը սեփականատիրոջ և ՀԾ ադմինիստրատորի համար է։ Կամրջի կոդը պատրաստ է, բայց **ոչ մի տեղ տեղադրված կամ միացված չէ**։ Գործող ERP-ին այս աշխատանքի ընթացքում միացում չի կատարվել։

## Ինչպես է աշխատում

Կայքը աշխատում է Linux-ի վրա (CT115, 192.168.1.24), իսկ ՀԾ-ի բիզնես օբյեկտները՝ միայն Windows-ում։ Կամուրջը կապում է այդ երկուսը.

```text
Կայք (RemoteNative) → HTTP → Windows ծառայություն AraqichErpBridge → AraqichErpNative.exe dispatch → ՀԾ բիզնես օբյեկտներ → 192.168.1.4 / SalesManagement
```

**Կամուրջն ու native ծրագիրը աշխատում են միայն Windows-ում, որտեղ տեղադրված է ՀԾ-ն, և չեն կարող աշխատել Linux կոնտեյներում։** CT115-ում աշխատում է միայն կայքի մասը։

Յուրաքանչյուր հարցման համար գործարկվում է առանձին կարճատև native գործընթաց։ Native-ը նույն կոդն է, ինչ փորձարկվել է տեղական պատճենում. տարբերվում են միայն թիրախն ու մուտքը։

**Պաշտպանությունը կամրջում**

- Յուրաքանչյուր հարցում ստորագրվում է ընդհանուր գաղտնի բանալիով (HMAC-SHA256)։ Ժամանակի թույլատրելի շեղումը ±120 վայրկյան է, նույն հարցումը երկրորդ անգամ չի ընդունվում։
- Ընդունվում են միայն թույլատրված IP հասցեները, առավելագույնը 2 ՄԲ մարմնով։ Թույլատրված են միայն վեց գործողություն՝ `options`, `preview`, `execute`, `status`, `reconcile-preview`, `reconcile-execute`։ Այս ստուգումները կատարվում են մինչև native գործընթացի գործարկումը։
- Կամրջի յուրաքանչյուր պատասխան նույնպես ստորագրված է։ Սխալ կամ բացակայող ստորագրության, ցանցային սխալի կամ ժամանակի սպառման դեպքում կայքը արդյունքը համարում է **անհայտ** և չի կրկնում հարցումը։
- Միայն նույնականացված հարցման պատասխանն է կապվում այդ հարցմանը։ Մինչև նույնականացումը մերժված հարցումները և կրկնված հարցումը կայքում դառնում են «անհայտ». դրանցով չի կարելի հաստատել, որ գրանցում չի եղել։

**Գրանցման սահմանափակումները**

- Ընթերցման գործողությունը 120 վայրկյանից հետո դադարեցվում է։
- Գրանցման գործողությունը (`execute`, `reconcile-execute`) **երբեք չի դադարեցվում**՝ ոչ ժամանակի սպառման, ոչ ծառայության կանգնեցման դեպքում։ 900 վայրկյանից հետո կայքը ստանում է «անհայտ» պատասխան, իսկ գործընթացը շարունակվում է. մինչ այն ավարտվի, մյուս հարցումները ստանում են «զբաղված» պատասխան։
- Ծառայության կանգնեցումը սպասում է ընթացիկ գրանցումների ավարտին։

**Native-ի ստուգումները**

Production տարբերակում չկան փորձնական ռեժիմները, private դաշտերի միջամտությունը և պահված SQL մուտքը։ SQL կապը հաշվարկում է ՀԾ-ի գրադարանը՝ ինչպես սեղանի ծրագիրը։ Մուտքից հետո և մինչև առաջին հարցումը ստուգվում են.

| Ստուգում | Պահանջվող արժեք |
|---|---|
| Բազա | `SalesManagement` |
| SQL մեքենա | `SQL-SERVER` |
| SQL տարբերակ | `14.0.1000.169` |
| ՀԾ գրադարան | `7.16.3.0` |
| ՀԾ օգտատեր | ադմինիստրատոր **չէ** |

Որևէ անհամապատասխանության դեպքում native-ը կանգ է առնում՝ առանց գրանցման։

**Երեք առանձին անջատիչ**

| Ֆայլ | Ազդեցություն |
|---|---|
| `WRITES_ENABLED.json` բացակայում է կամ սխալ է | Գրանցումն անջատված է։ `execute`-ը և `reconcile-execute`-ը մերժվում են `writes_disabled` պատասխանով՝ մինչև որևէ Store։ |
| `WRITES_ENABLED.json` = `{"max_orders": N}` | Գրանցումը թույլատրված է, մեկ գործարկումում՝ առավելագույնը N պատվեր։ |
| `QUARANTINED.json` կա | Նոր գրանցումները արգելված են, ընթերցումը մնում է հասանելի։ |

Տեղադրման սկրիպտը `WRITES_ENABLED.json` **չի ստեղծում**։ Այն կարող է ստեղծել միայն ադմինիստրատորը՝ ձեռքով։

| `C:\ProgramData\AraqichErpBridge\private-config.json` | `erp_user` և DPAPI-ով պաշտպանված `erp_password_protected`։ SQL մուտք չի պահվում։ |

## ՀԾ օգտատիրոջ իրավունքները

Անհրաժեշտ է առանձին օգտատեր, որը **ադմինիստրատոր չէ**։ Ստորև բերված ցանկը ստուգվել է տեղական պատճենում՝ իրական `probe`, `options`, `preview` և `execute` կանչերով (երկու հաջող գրանցում, սովորական մեկ ապրանքով պատվերներ)։ Փակագծերում նշված է տվյալների աղյուսակը՝ ստուգման համար։

| Ինչ պետք է կարգավորել | Արժեք |
|---|---|
| Օգտատեր | Մուտքը թույլատրված, ադմինիստրատորի դրոշակը անջատված (`USERS`)։ |
| Դեր | Առանձին դեր՝ կցված այս օգտատիրոջը (`USERSROLES`)։ |
| Ենթահամակարգ | Դերին՝ «Վաճառքներ» ենթահամակարգը, կոդ 1 (`SUBSYSTEMACCESS`)։ Առանց ենթահամակարգի մուտքը մերժվում է։ |
| Աշխատանքային ժամանակահատված | Դերին՝ սկիզբ և ավարտ, որոնք ներառում են այսօրը (`ROLEPARAMS` 24001–24005)։ Առանց դրա առաջին գրանցումն ընդհատվում է ծրագրային սխալով։ |
| «Վաճառքի պատվեր» (տիպ 1) | Խմբագրում (`DOCUMENTACCESS`)։ |
| «Ապրանքների պահուստավորում» (տիպ 29) | Ստեղծում։ |
| «Ապրանքների տրամադրում» (տիպ 19) | Ստեղծում։ |
| «Վաճառք» (տիպ 2) | Ստեղծում։ |
| Պահեստներ | Յուրաքանչյուր բեռնման պահեստի համար՝ ելք և մնացորդ (`STORAGESACCESSBYUSERS`)։ Չհասանելի պահեստը չի երևում կայքի ցանկում։ |

Դիտման, ջնջման և տեղեկատուների իրավունքներ, ինչպես նաև `USERDB` գրառումներ հաջող փորձերում **չեն տրվել** և չեն պահանջվել։

**Կարևոր զգուշացումներ**

- Իրավունքների պակասը երևում է միայն գրանցման պահին. նախադիտումը դա չի բացահայտում։ Պատճենում պահուստավորման իրավունքի բացակայության դեպքում պատվերն արդեն փոխվել էր (առաքիչ և մեքենա), իսկ արդյունքը եղել է «անհայտ»։ Ուստի բոլոր իրավունքները սահմանեք **մինչև** առաջին գրանցումը։
- Ծառայողական օգտատիրոջ դերի աշխատանքային ժամանակահատվածը պետք է **երկարաձգել ամեն տարի**։ Ժամկետից դուրս առաջին Store-ը կձախողվի։ Պատճենում գործող դերերի ժամկետն ավարտվում է `31.12.2026`-ին։
- Իրավունքները ստուգվել են միայն սովորական մեկ ապրանքով պատվերների վրա։ Համադրումը (`reconcile-*`), նվերները և «ի պահ» տողերը ոչ ադմինիստրատոր օգտատիրոջով չեն փորձարկվել։

## Տեղադրում

Բոլոր քայլերը կատարում է ադմինիստրատորը Windows համակարգչում, որտեղ տեղադրված է ՀԾ-Վաճառքների կառավարում 7.16.3։

1. Ստեղծեք ՀԾ օգտատերը՝ վերևի ցանկով։
2. Կառուցեք ֆայլերը՝ `native\armsoft_bridge\Build-Bridge.ps1`։ Արդյունքը և SHA256 ցուցակը կլինեն `G:\Araqich-ERP-Bridge-Build-20261109\` պանակում։
3. Ադմինիստրատորի իրավունքներով գործարկեք.

   ```powershell
   .\Install-AraqichErpBridge.ps1 -BuildDir 'G:\Araqich-ERP-Bridge-Build-20261109' -ErpUser 'ՕԳՏԱՏԻՐՈՋ_ԱՆՈՒՆԸ'
   ```

   Սկրիպտը կխնդրի ՀԾ գաղտնաբառը, կստեղծի գաղտնի բանալին, ծառայությունը (ձեռքով մեկնարկ, `NT SERVICE\AraqichErpBridge`), URL-ի թույլտվությունը և firewall կանոնը՝ միայն `192.168.1.24`-ի և `8765` պորտի համար։ Կրկին գործարկելիս գաղտնիքները պահպանվում են, եթե չեք նշել `-RotateSecrets`։
4. `C:\ProgramData\AraqichErpBridge\site-hmac-secret.txt` ֆայլը տեղափոխեք CT115 և **ջնջեք Windows-ից**։ CT115-ում ֆայլի հասանելիությունը սահմանափակեք միայն կայքի հաշվով։
5. CT115-ում ավելացրեք երեք փոփոխական։ Երեքն էլ պարտադիր են, հակառակ դեպքում շղթան անջատված է.

   ```text
   ROUTES_ERP_CHAIN_BRIDGE_URL=http://WINDOWS_ՀԱՄԱԿԱՐԳՉԻ_IP:8765
   ROUTES_ERP_CHAIN_BRIDGE_SECRET_FILE=/բանալու/ֆայլի/ուղին
   ROUTES_ERP_CHAIN_JOURNAL=/մատյանի/ուղին/erp-chain-journal.sqlite3
   ```

   Հասցեն պետք է լինի մասնավոր ցանցի կամ loopback IP։ `ROUTES_ERP_CHAIN_LOCAL_ROOT`-ը նույն ժամանակ նշել չի կարելի։
6. **Վերագործարկեք կայքը**, որպեսզի փոփոխականները կիրառվեն։ Սխալ կարգավորման դեպքում կայքը շարունակում է աշխատել, բայց այս գործառույթն անջատված է, իսկ պատճառը գրվում է կայքի մատյանում։

## Փուլային միացում

Յուրաքանչյուր փուլից հետո ստուգեք արդյունքը, հետո միայն անցեք հաջորդին։

**1. Միայն ընթերցում։** Համոզվեք, որ `WRITES_ENABLED.json` չկա։ Ադմինիստրատորի PowerShell-ից, առանց պատուհանի (`ProcessStartInfo`, `CreateNoWindow`), գործարկեք `AraqichErpNative.exe probe`-ը։ Պետք է ստանաք `native_login_verified`, `database` = `SalesManagement` և ճիշտ օգտատերը։ Ապա գործարկեք ծառայությունը՝ `Start-Service AraqichErpBridge`, և CT115-ից ուղարկեք ստորագրված `options` հարցում։ Պատասխանում պետք է լինի `environment` = `production`, `writes_enabled` = `false` և պահեստների ցանկը։ Այս քայլը ոչինչ չի գրանցում։

Ժամանակավոր առաջադրանքով ստուգումը չի աշխատում. Windows-ի առաջադրանքների պլանավորիչը չի ընդունում `NT SERVICE` հաշիվը։ Ծառայության հրամանը ժամանակավորապես փոխարինելն էլ արդյունք չի տալիս։ Առաջին մեկնարկը կարող է ձախողվել 30 վայրկյանի սահմանով. կրկնեք։

**2. Նախադիտում։** Գործարկեք ծառայությունը՝ `Start-Service AraqichErpBridge`։ Կայքում բացեք «Տրամադրում և վաճառք»։ Պահեստների ցանկը պետք է բացվի, իսկ նախադիտումը՝ ցույց տա պատվերները։ Պատուհանի վերևում երևում է գործող ERP-ի նշումը և «գրանցումն անջատված է» տեքստը։ Հաստատելու փորձը պետք է մերժվի՝ «գրանցումը դեռ միացված չէ»։

**3. Մեկ պատվեր։** Կայքը ընտրում է ամբողջ երթը, ոչ առանձին պատվեր։ Ուստի ընտրեք **ճիշտ մեկ պատվեր ունեցող երթ**։ Եթե այդպիսին չկա, `max_orders`-ը գիտակցաբար սահմանեք այդ երթի պատվերների քանակին։ Ստեղծեք ֆայլը.

```powershell
Set-Content -LiteralPath 'C:\ProgramData\AraqichErpBridge\WRITES_ENABLED.json' -Value '{"max_orders": 1}' -Encoding Ascii
```

Պատուհանում պետք է երևա «գրանցումը միացված է» և սահմանված քանակը։ Հաստատեք կայքից մեկ պատվեր։ ՀԾ ծրագրում ստուգեք տրամադրումը, վաճառքը, գումարը, պահեստի մնացորդն ու հաճախորդի պարտքը։ Ապա նորից ջնջեք ֆայլը, մինչև արդյունքը ամբողջությամբ ստուգվի։

**4. Ընդլայնում։** Միայն հաջող ստուգումից հետո մեծացրեք `max_orders`-ը աստիճանաբար։ Առավելագույնը 100 է։

## Ինչպես անջատել

| Նպատակ | Գործողություն |
|---|---|
| Անմիջապես դադարեցնել նոր գրանցումները | Ջնջել `WRITES_ENABLED.json`-ը։ Ընթացիկ գրանցումը կավարտվի։ |
| Արգելել գրանցումները ստուգման ժամանակ | Ստեղծել `QUARANTINED.json`՝ նույն պանակում։ |
| Արգելել գրանցումները հենց կայքից (CT115) | Ստեղծել `QUARANTINED.json`՝ `ROUTES_ERP_CHAIN_JOURNAL` մատյանի պանակում։ |
| Կանգնեցնել կամուրջը | `Stop-Service AraqichErpBridge`։ Ծառայությունը կսպասի ընթացիկ գրանցման ավարտին։ |
| Անջատել շղթան կայքում | Հեռացնել երեք `ROUTES_ERP_CHAIN_*` փոփոխականները և վերագործարկել կայքը։ |

**Երբեք մի դադարեցրեք** `AraqichErpNative.exe` գործընթացը ձեռքով և մի անջատեք համակարգիչը ընթացիկ գրանցման ժամանակ։ Մի ջնջեք `dispatch` պանակի ֆայլերը. դրանք կրկնակի գրանցումից պաշտպանող մատյանն են։

## Երբ արդյունքը «անհայտ» է

Անհայտ արդյունքը նշանակում է, որ կայքը չի կարող հաստատել՝ գրանցումը կատարվել է, թե ոչ։ Պատվերներն ու պլանը մնում են պաշտպանված։ Օգտագործեք «Ստուգել արդյունքը». այն միայն կարդում է ՀԾ-ն։ Նույն հաստատումը ինքնաշխատ չի կրկնվում։

Բրաուզերը սպասում է մինչև 160 վայրկյան, իսկ nginx-ը պատասխանը պահում է 180 վայրկյան (`proxy_read_timeout 180s`)։ Ավելի երկար գրանցման դեպքում էջը ցույց կտա «գրանցումը կարող է դեռ ընթանալ», իսկ գործընթացը Windows-ում կշարունակվի մինչև ավարտ։ Սեղմեք «Ստուգել արդյունքը»։ Քանի դեռ ERP-ի գործողությունն ընթանում է, արդյունքը կլինի «Գրանցումն ընթացքի մեջ է»։

Եթե տրամադրումը գրանցված է, իսկ վաճառքը՝ ոչ, կիրառեք «Համադրել և լրացնել» ընթացակարգը՝ [փորձնական հոսքի նկարագրությամբ](erp-chain-local.md)։

**Ստուգեք նորից մոտ 12 րոպե անց։** Եթե գրանցման մատյան չկա, native-ը կարող է ինքը ապացուցել, որ գրանցում չի եղել և այլևս չի կարող լինել․ նախադիտման ժամկետն անցել է (10 րոպե), պատվերների տարբերակները չեն փոխվել, և պատվերներից ստեղծված փաստաթուղթ չկա։ Այդ դեպքում կայքը ինքնաշխատ ազատում է պլանն ու պատվերները։ Այդ ապացույցը տալիս է միայն native-ը։ Եթե որևէ պայման չի բավարարվում, պլանը մնում է կողպված։

**Մատյանը ջնջելը ոչինչ չի ապացուցում։** Իրական գրանցումից հետո ջնջված կամ անընթեռնելի մատյանը կայքը չի համարում «գրանցում չի եղել»․ պլանը մնում է կողպված։ Մի ջնջեք մատյանները՝ պլանն ազատելու համար։

**Պլանի ձեռքով ազատում։** Եթե արդյունքը մասնակի կամ անորոշ է և գործողությունն այլևս չի ընթանում, արդյունքի պատուհանում հասանելի է «Ազատել պլանը» գործողությունը։ Այն կարելի է օգտագործել միայն ՀԾ-ում փաստաթղթերը ձեռքով ստուգելուց հետո։ Պահանջվում են Superadmin-ի հաստատում և 10–500 նիշով պատճառ։ Օգտատերը, ժամանակը և պատճառը պահպանվում են։ Հանվում է **միայն պլանի կողպեքը**․ պատվերները մնում են զբաղված, որպեսզի դրանք երկրորդ անգամ չգրանցվեն։ Քանի դեռ ERP-ի գործողությունն ընթանում է, ազատումը մերժվում է։

## Ինչը դեռ չի ստուգվել

Հետևյալը տեղական պատճենում հնարավոր չէր ստուգել, և պետք է ուշադիր դիտարկել առաջին փուլերում.

- Ծառայության հաշվով և session 0-ում աշխատանքը, ինչպես նաև ծառայության կառավարչի կանգնեցումն ու համակարգչի անջատման ճյուղը։ LocalDB-ն միացված է կոնկրետ օգտատիրոջ, ուստի փորձերն արվել են `--console` ռեժիմում։
- ՀԾ գրադարանի կողմից հաշվարկվող SQL կապը գործող սերվերին։
- Production տարբերակի մուտքից հետո կատարվող ստուգումները. դրանք կոդում կան, բայց իրական սերվերի բացակայությամբ չեն գործարկվել։
- `Install-AraqichErpBridge.ps1` սկրիպտը ստուգվել է միայն շարահյուսությամբ։
- Արտաքին հարկային/ՀԴՄ/մակնշման ուղարկումը և ֆիզիկական բեռնումը։

Կապը ստորագրված է, բայց **գաղտնագրված չէ**. պատվերների տվյալները ներքին ցանցում փոխանցվում են բաց տեսքով։
