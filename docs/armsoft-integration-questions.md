# ՀԾ-ի հետ ճշտելու տեխնիկական հարցեր

Սա պատրաստված հարցաշար է. այն ՀԾ-ին չի ուղարկվել։ Օգտատերը նշել է, որ առանձին SDK փաստաթուղթ կամ տեխնիկական կոնտակտ չունի։

## Գործընթացը

Տեղադրված համակարգը ՀԾ-Վաճառքների կառավարում 7.16.3 է, իսկ գործող SQL Server-ի ուսումնասիրված տարբերակը՝ 2017 / 14.0.1000.169։ Կայքը պետք է ուղարկված երթի պատվերներին նշանակի առաքիչ և մեքենա, ստեղծի գրանցված «Ապրանքների տրամադրում առաքիչին», ապա յուրաքանչյուր պատվերի հետ կապված գրանցված «Վաճառք»։

[Վաճառքի պատվերների պաշտոնական օգնությունը](https://online.armsoft.am/salesmanagement/salesorders.htm) և [տրամադրումների օգնությունը](https://online.armsoft.am/salesmanagement/productsprovidings.htm) նկարագրում են այս փաստաթղթերի աշխատանքը։ Այդ նկարագրությունը ինքնին արտաքին Windows ծառայության SDK-ի կամ միացման թույլտվության պայմանագիր չէ։ ՀԾ-Առևտրի համար հրապարակված [ամպային REST API-ն](https://online.armsoft.am/trade7/restapi.htm) այս տեղադրված այլ համակարգի API համարելու հաստատում չունենք։

## Անհրաժեշտ պատասխանները

1. Այս տարբերակի համար ո՞ր API/SDK-ն և լիցենզիան են նախատեսված արտաքին ծրագրից կապված պատվեր→տրամադրում→վաճառք գրանցելու համար։ Խնդրում ենք տրամադրել պաշտոնական փաստաթուղթ և օրինակ։
2. Թույլատրելի՞ է բիզնես օբյեկտների օգտագործումը առանձին Windows ծառայությունից՝ առանց բաց գրասենյակային ծրագրի։ Ի՞նչ պահանջներ կան օգտատիրոջ, STA հոսքի, աշխատանքային կայանի և սեսիայի նկատմամբ։
3. Ինչպե՞ս է ծառայությունը պաշտոնական եղանակով անցնում ՀԾ-ի օգտատիրոջ նույնականացումը և ստանում սահմանափակ SQL կապը՝ առանց գաղտնիքին կամ private դաշտերին միջամտելու։ Պահանջվում է ծառայության առանձին հաշիվ, ոչ `sa` կամ sysadmin իրավունք։
4. Արդյո՞ք `SalesOrder`, `ProductsProviding` և `Sale` օբյեկտների կիրառումը, պատվերի `Parents` կապը և `StoreRequest { MakeDraft=false }` գրանցումը արտաքին ինտեգրման համար աջակցվող պայմանագիր են։ Եթե ոչ, ո՞ր պաշտոնական մեթոդներով պետք է փոխարինել։
5. Ինչպե՞ս պետք է պաշտպանել պատվերը գրասենյակի կամ այլ ինտեգրման միաժամանակյա փոփոխությունից։ Կա՞ պաշտոնական փաստաթղթի կողպեք, տարբերակի վերահսկում կամ idempotency բանալի։
6. Տրամադրումը պահպանվել է, վաճառքը՝ ոչ. ինչպե՞ս է առաջարկվում ստուգել փաստացի արդյունքը և ստեղծել միայն բացակայող վաճառքը։ Ինչպե՞ս պետք է ստուգել անհայտ արդյունքը՝ առանց կրկնակի փաստաթղթի։
7. Ի՞նչ է պաշտոնական կանոնը նվերների, ի պահ և վճարովի տարաների ու փոխանակումների համար։ Խնդրում ենք տրամադրել քանակների, գումարների և պարտքի շարժման ստուգման օրինակներ։
8. Կարո՞ղ են սովորական գրանցումները ինքնաշխատ կանչել ՀԴՄ, հարկային կամ b2b/շարժական ուղարկում։ Ինչպե՞ս են դրանք կառավարվում փորձնական և գործող միջավայրերում։
9. SQL2017-ի և ծրագրի այս տարբերակի համար ո՞ր թարմացումներն ու SQL compatibility մակարդակն են պահանջվում։

## Տեղային արդյունքը

Փորձարկման կոդը և native մուտքը սահմանափակված են այս համակարգչի առանձին պատճենով։ Գործող ERP-ում գրանցման ծառայություն չի տեղադրվել և չի միացվել։ Մինչև վերը նշված պատասխանները ներկա փորձնական մուտքի private-field կարգավորումը չի ներկայացվում որպես պաշտոնապես հաստատված production ինտեգրում։
